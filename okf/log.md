# Bundle Update Log

## 2026-06-29
* **Standard + feature**: the **[App manifest](/concepts/app-manifest.md)** — a standard way for a Void Core app to *introduce itself*, proposed by the FaultSack agent (`/design/app-manifest-design.md`; decisions in `/design/app-manifest-design.md`). A reserved bundle-root concept `app.md` of `type: Manifest` carries **identity** (name/id/version/description/+authors/repo/status) and an optional **representation** layer (`palette.<role>` + `icon` + `theme`, normative-small, plus a free `theme.*` bag — the tag-axis shape). Read via the [OKF holiday](/components/okf-engine.md): `holidays/okf/manifest.py` `read_manifest()` returns it with graceful fallbacks (app.md → index.md frontmatter → index.md heading/paragraph scrape → folder name), **subsuming FaultSack's scrape workaround**. Data, not engine behavior (the core renders nothing; assets belong to a renderer holiday, `planned`). Added Void Core's own `okf/app.md`; `validate` exempts `type: Manifest` from the code-`resource:` rule. Tested `holidays/okf/manifest_test.py`.
* **Adoption**: studied Matt Pocock's ["Skills For Real Engineers"](https://github.com/mattpocock/skills) (MIT). Installed six OKF-compatible workflow skills under `.claude/skills/` (`codebase-design`, `tdd`, `diagnosing-bugs`, `grilling`, `grill-me`, `handoff`), lightly adapted so domain-vocabulary pointers also read this project's OKF bundle. Deliberately skipped `grill-with-docs`/`domain-modeling` (impose a CONTEXT.md/ADR layout overlapping OKF) and the issue-tracker/triage process machinery.

## 2026-06-28
* **Feature**: **effect handler bound + generic `effect` verb** (the [holiday](/concepts/holiday.md) boundary — DAW + Hormiga's last ask). `vc_set_effect_handler` is now bound in the Python binding (`VoidCore.set_effect_handler(fn)`, `fn(op, args) -> dict|str|None`); `save`/`deploy`/`build`/`preview` reach Python, and a new C **`effect <op> [args...]`** verb routes *any* host op through the seam and returns its result as `data` — so the holiday `query(tagExpr) -> [rune]` interface is reachable today (Hormiga: `effect query "<expr>"`). Cross-allocator safety via a new public `vc_alloc_str` (host builds the return with the library's allocator; the core frees it) — verified with 200 alloc/free round-trips, no crash. C ABI additions: `vc_alloc_str`, the `effect` verb. DLL rebuilt; C smoke + Python binding smoke pass. Tested `bindings/python/effect_test.py` (save routing, `effect`→data, no-handler failure). `SPEC.md` §7/§9 updated.
* **Feature**: **`materialize` provenance** (Hormiga's ask) — `provenance(obj)` ([Scry](/concepts/scry.md), `from voidcore import provenance`) is a stable, order-independent snapshot id (sha256/16) of any JSON value; `materialize(..., stamp=<field>)` / the `materialize --stamp <field>` verb record `content[stamp] = provenance(baked fields)`, so a frozen archive proves *what snapshot it captured* and a reader can tell if live data still matches. Pure (no clock). Tested in `scry/projection_test.py` + `voidcore/dispatch_test.py`.
* **Feature**: **atomic single-frame undo** for transform passes — the seam now applies a multi-write `temper`/`materialize`/temper-on-write/`reduce --commit` pass as **one** undo frame via the C core's `batch` verb (one snapshot, rolled back on any failure), instead of one frame per write-back (the PM + Hormiga ask). `Dispatcher._run()` wraps the collected commands in `batch`. **C core fix:** the `args.c` tokenizer's per-token buffer is now **dynamic** (was capped at 1023 chars), so a large `batch` payload is never truncated — verified a 300-command / 4390-char batch (DLL rebuilt, C smoke + Python binding smoke pass). Tested in `voidcore/dispatch_test.py` (a 3-rune materialize = 1 history frame; one undo reverts all three). `SPEC.md` §7 updated.
* **Feature**: **Reduce authored as data + the `reduce` dispatcher verb** — `voidcore.spec.reducer_from_spec` compiles a `{signatures, rules}` spec (port arities + glyph-pair `annihilate`/`commute` rules) into a `Reducer`, and the seam's **`reduce [--into <name>] [--commit]`** verb builds the active mantle's net (ports ride each edge's `relation` as `"i:j"`), reduces to normal form, returns the derived mantle (preview; source untouched), and `--commit` installs it live. The reducer rides in `config.transform.reduce` and loads via `Dispatcher.load_from_config()` — so a mantle carries its own rewrite rules. This **unblocks the previously-reserved `reduce` verb** ([Reduce](/concepts/reduce.md)); the executor was already built. The conflict guard still applies (≤1 rule/glyph-pair). Tested `voidcore/reduce_verb_test.py`. (`expand` stays code-registered — needs a custom build fn.)
* **Feature + integration**: **`Lens`** — a bidirectional [Scry](/concepts/scry.md) projection (`forward` + `backward`) that inherits the round-trip law (`scry/lens.py`, `from voidcore import Lens`; `LocalJsonHoliday.lens()`). The Portfolio Manager refactored its **triplicated** tag mapping (persistence + form read `_tag_state` + form write `_sync_tags`) to route all three through the one `Lens` — the drift surface where its lossy-tag bug lived is gone; `scry_law_test` now calls `lens.check()`. Verified: lens test (record↔rune law + lossy schema caught), PM scry-law LOSSLESS on 4 real projects, phase 0, temper integration, and a CRUD tag round-trip all green. Second slice of data-authored specs (the persistence-mapping-as-spec'd-Selector ask).
* **Feature**: **data-authored transformation specs** — `voidcore/spec.py` (`temper_from_spec`, `selector_from_spec`, `temper_rule_names`): JSON specs that compile to the same tested [Temper](/concepts/temper.md)/[Scry](/concepts/scry.md) objects (code stays the reference; data is a serialization). They ride in the **state document** under `config.transform` and the [dispatcher](/concepts/dispatcher.md) seam loads them via `Dispatcher.load_from_config()` / `load_specs()` — so rules persist + reload with the data they govern (author JSON → store in state → reopen → verbs work, no code). First slice of the app-agents' top strategic ask (DAW editable rules / PM mapping-as-data / the reserved `reduce` verb's rules-as-mantle-data). Tested `voidcore/spec_test.py` (compile parity vs code-built, state-doc round-trip driving `scry --select` + temper-on-write, validation errors). `SPEC.md` §7 updated.
* **Feature**: **temper-on-write** — opt-in `Dispatcher.temper_on_write()` runs the registered [Temper](/concepts/temper.md) pass automatically after every mutating verb, re-normalizing the targeted rune(s), so canonical-form invariants hold even for **raw** dispatcher edits (the Portfolio Manager's #1 correctness ask — it exposes a raw dispatcher to users). Off by default (non-breaking); targets only affected runes; idempotent. Tested in `voidcore/dispatch_test.py` (raw `setjson` invariant repair, tag-dedupe, targeting, default-off). `SPEC.md` §7 updated.
* **Deferred**: shelved **inter-application communication** as a research concept (`okf/roadmap.md`) — a protocol layer for apps on Void Core to discover/talk to each other on top of the OKF, incl. the "update other agents" pattern. Noted, not pursued now.
* **Fix + feedback**: from the app agents' handoff replies (`/design/transform-layers.md`): (1) **bug** — the `scry` dispatcher verb silently folded `--tag` into the filter as a literal token (Portfolio Manager hit `scry --tag "featured"` → 0). Worked example `scry/bilingual_example.py`; seam regression in `voidcore/dispatch_test.py`. Confirmed: all three apps validated the contract and none are blocked.
* **Integration**: the three transformation layers are now [dispatcher](/concepts/dispatcher.md) verbs — `scry`/`temper`/`materialize` (and reserved `reduce`) — via a **seam**, `voidcore.Dispatcher`: a drop-in superset of `VoidCore.dispatch` that handles the transform verbs and delegates everything else to the [C core](/components/c-core.md) unchanged. Implemented once (the tested Python layers), not duplicated into C; mutating verbs write back through `setjson`/`tag` so they stay undoable. Normative contract added to `SPEC.md` §7 ("Transformation verbs", new `[seam]` status key). Tested in `voidcore/dispatch_test.py` (delegation parity, scry + `--select`, temper, materialize, undo).
* **Integration**: Portfolio Manager adopted the [Temper](/concepts/temper.md) layer — its hand-coded thumb/images invariants in `core.py` (the add_image/remove_image/set_thumb branches) are replaced by a declarative `Temper([dedupe, member_or_default, single_tag, normalize_tags])` pass applied through the dispatcher (so it stays undoable). Parity + persistence verified (`voidcore_app/temper_integration_test.py`); the [Scry](/concepts/scry.md) round-trip guard still LOSSLESS on the 4 real projects, phase 0 green. First real-app proof of a transformation layer; first hand-coded invariant deleted in favor of the library.
* **Creation**: [Reduce](/concepts/reduce.md) — the interaction-net **executor** — `VoidCore/reduce/` (`Reducer`, `Net`/`Agent` with principal+aux ports, `annihilate`/`commute`/`expand`, `to_net`/`from_net`), exported from the `voidcore` package. The third and last transformation layer. Resolved all **five open forks** (`/design/transform-layers.md`): restricted confluent subset with a registration-time conflict guard, `reduce(net)->net` (pure, effect-free), active-pairs-only (feedback cycles preserved + explicit opaque), transient `expand` vs durable `materialize`, explicit/previewable scheduling. Laws property-tested — identity, normal form, **strong confluence under 40 randomized schedules of the full γδε interaction-combinator system**, termination guard, locality/linearity, opaque pass-through, purity (`reduce/reduce_test.py`). This realizes the executor [interaction nets](/concepts/interaction-nets.md) reserved; the three-layer track (Reduce/Temper/Scry) is now built.
* **Creation**: [Temper](/concepts/temper.md) normalization layer — `VoidCore/temper/temper.py` (`Temper`, `dedupe`, `member_or_default`, `default_content`, `default_tag`, `normalize_tags`, `single_tag`), exported from the `voidcore` package. Pure `rune -> rune` rules centralizing the invariants the Portfolio Manager hand-codes (thumb = images[0], image/tag dedupe, status defaulting/collapsing). The **idempotence law** `temper(temper(x)) == temper(x)` + purity are property-tested (`temper/temper_test.py`). Second of the three transformation layers; Reduce remains.
* **Creation**: [Scry](/concepts/scry.md) projection layer — `VoidCore/scry/projection.py` (`scry`, `materialize`, `tag_match`, `Context`, `Selector`), exported from the `voidcore` package. * **Creation**: [Scry](/concepts/scry.md) round-trip law — `VoidCore/scry/roundtrip.py` (`check_roundtrip`), the `unscry(scry(x))==x` harness. Verified LOSSLESS on the live Portfolio Manager's real projects and shown to catch the lossy-projection class it shipped; regression guard added in the app.
* **Decision**: Locked the three-layer build order **Scry → Temper → Reduce** (easiest/fork-free → hardest); [Reduce](/concepts/reduce.md) gated on the open forks. Clarified [interaction nets](/concepts/interaction-nets.md) is not a separate build item — its executor *is* Reduce.
