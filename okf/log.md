## 2026-07-03
* **Feature — POSIX command surface (SPEC §7.1, from `HORMIGA_HANDOFF.md` §2)**: the CLI now speaks terminal — **mantle ≈ directory, rune ≈ file, tag expression ≈ glob**. Aliases are **argument-aware desugarings** rewritten to canonical argv *before* routing (one semantics, many spellings; undo labels and mutation classification see the canonical form): `cd`→`use`, `pwd`→`where`, `rm <ref>`→`rune rm <ref>` (replacing the old bare `rm`→`rune` alias, under which `rm x` was a usage error), `mv`→`rune rename`, `cp`→`rune dup`, `mkdir`→`mantle new`, `grep`→`find`, `man`/`?`→`help`, `quit`→`exit`, `dump`→`export`. Cold-start ergonomics: **root-`ls`** (no active mantle) lists the mantles instead of erroring, and **`use` with no args (or `cd /`) deactivates** back to the mantle list. Implemented in **both** the C core (`args.c` `vc_argv_desugar`) and the JS oracle (which also lost its `mantles[0]` active-mantle fallback — strict by-name resolve, matching `vc_active_mantle`, so "no active mantle" is a real state in both impls). This also **closes the conformance gap** the handoff flagged: the C core had *none* of the §7 aliases the spec declared (`pwd` → unknown verb).
* **Fix (C core, exact repro from the handoff)**: `ls --tag <expr>` joined **every** token after `--tag` into the tag expression, so a trailing `--json` became a literal AND-term — `let n = $(ls --tag month:june --json)` returned `[]` (and so did the direct form). The join now stops at the next `--flag`. Conformance case `08-capture-flags.vs` locks it (direct + capture + `foreach` paths); `07-posix.vs` locks the whole §7.1 surface. **8/8 cases pass**; both new cases behavior-checked against the JS oracle too.
* **Feature — the §5 tag grammar over the FFI (handoff §3.1)**: new ABI export **`vc_tag_match(expr, tags_json) -> 1|0|-1`** (stateless, thread-safe; bound as `VoidCore.tag_match(expr, tags)`): one C implementation of the filter grammar for hosts filtering *external/holiday* entities, so Hormiga's `hormiga_core/tagexpr.py` and `holidays/meshdb/tag_filter.py` can be deleted in favor of the seam and `effect query "<expr>"` means exactly what `ls --tag` means. SPEC §5 now mandates evaluating through this seam.
* **Docs — threading contract (handoff §3.3)**: SPEC §6 + `voidcore.h` now state it: a `VC_Manager` is **not thread-safe**; serialize all calls per instance (Hormiga's per-manager lock is the intended pattern); callbacks run synchronously inside the dispatch and must not re-enter; distinct managers are independent; `vc_tag_match`/`vc_alloc_str`/`vc_free_str`/`vc_version` are safe anywhere.
* **Distribution (handoff §1)**: version bumped **0.1.0 → 0.2.0** in the four places it lives (`pyproject.toml`, `package.json`, `vc_version()`, `VC_VERSION_STR`); SPEC header → v0.2. New **GitHub Actions workflow** (`.github/workflows/ci.yml`): win/mac/linux matrix builds the shared library, runs the C smoke test + the full conformance suite per platform, and on a `v*` tag publishes `libvoidcore-win-x64.dll` / `libvoidcore-macos-universal.dylib` / `libvoidcore-linux-x64.so` as a GitHub Release — the concrete unblock for Hormiga's degraded mac/linux console (its `vendor_voidcore.py --from-release <tag>` mode). CMake: `-static-libgcc` now skipped on Apple. *(Not done here: committing/pushing the mirror — needs Miguel's secret sweep sign-off; import-hygiene subpackaging (handoff §3.4) deliberately deferred as "not urgent".)*
